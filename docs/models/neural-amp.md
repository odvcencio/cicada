# Causal neural amp

`neural_amp(audio, drive)` adds an original, trained nonlinear amp to a voice graph.
The amp runs entirely in Go with pinned integer weights. The model, activation table,
and procedural training data are dedicated to CC0-1.0; the engine and training script
retain the repository's MIT license. No third-party recording or model is included.

```cicada
instrument picked {
  param drive: unit = 2.5
  voice mono {
    let source = saw(pitch) * env(gate, 230ms) * velocity
    out = neural_amp(source, drive) * 0.3
  }
}
```

Render the complete demo:

```sh
GOWORK=off go run ./cmd/cicada render examples/neural-amp.cicada \
  -o build/neural-amp.wav --rate 48000 --bits 24 --bars 2 --tail 1s
```

## Model and provenance

This NAM-style model is a causal convolutional network: eight audio-history taps,
four tanh channels and a learned linear readout. All 36 coefficients are trained;
there are no biases, so zero input with empty history produces exact silence.
It is a small original amp, rather than a loader for Neural Amp Modeler `.nam` files
or a capture of commercial hardware. Its fictional reference combines nonlinear
saturation and a short tone-filter memory. Acoustic similarity depends on the fitted model and source recording.

[`kernel/amp/model.json`](../../kernel/amp/model.json) pins the architecture, seed,
quantization, held-out results and SHA-256 of little-endian int16 convolution
weights, output weights and activation table, concatenated in that order.
[`kernel/amp/LICENSE-CC0`](../../kernel/amp/LICENSE-CC0) contains the full CC0-1.0
terms. Cicada contributors dedicate the original model coefficients, activation
table and all audio generated by `tools/train-neural-amp.py` to
[CC0-1.0](https://creativecommons.org/publicdomain/zero/1.0/).
The original generated corpus contains tones, chirps, plucks, noise and impulses;
no downloaded dataset, recording, attribution obligation or personal metadata
enters the weights.

The 48 kHz training corpus has 65,536 frames. The independent held-out seed creates
32,768 frames. The model uses 72 bytes of coefficients, a 514-byte tanh table and 32 bytes of
history per graph node. The kernel allocates history when constructing a voice.

## Train outside the kernel

Python 3 and NumPy 2.3.5 are the only training dependencies. The script forces
single-threaded BLAS, seeds every random draw, generates its own CC0 paired data,
then runs 6,000 Adam minibatches. It exports Go int16 arrays and the model manifest.
The reference is procedural DSP; the model does not reproduce a recorded amplifier.

```sh
python3 -m venv .venv-neural
.venv-neural/bin/pip install numpy==2.3.5
.venv-neural/bin/python tools/train-neural-amp.py --output kernel/amp
GOWORK=off gofmt -w kernel/amp/weights.go
GOWORK=off go test ./kernel/amp -count=1 -v
```

Floating training can vary in its last bits across BLAS/platform versions. The
committed integer arrays are the runtime authority and never retrain at load time.
Training and evaluation use disjoint random seeds. The manifest records results
from integer table-interpolated inference, rather than floating training loss.

## Determinism, rate and limits

Audio/history uses Q15, drive Q12, convolution coefficients Q12 and readout
coefficients Q14. Integer accumulations use int32; the pinned-weight test proves
each row/readout's absolute-weight sum stays below 32767, keeping Q15 products
below 2^30. Tanh uses a bounded, monotonic
257-entry table with integer interpolation; every shift and clamp is explicit.
The float32 bridge multiplies/divides by powers of two and clamps NaN/infinity
before conversion. Drive is bounded to 0..8. Oversized audio clips to Q15.
A graph node owns independent history, and voice reset/copy handles it without
render-time allocation. The node introduces no lookahead and drains in eight
samples once its input becomes zero.

Training targets 48 kHz. The existing 44.1/96 kHz engine rates are accepted with
identical sample-domain processing; the short tone memory changes its time scale.
The model does not oversample, so strong drive can alias. It neither claims hardware
capture fidelity nor covers long cabinet responses, gain-dependent envelopes or
external NAM model loading.
