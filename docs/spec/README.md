# Cicada language specification

This specification defines Cicada source editions 1 and 2, their typed project model, and the constructs approved for later implementation.

## Status labels

- **Implemented** means the construct is available in the current build and accepted by the validator.
- **Accepted** means the design has been reviewed, but it is not available in the current build. Examples use cicada-accepted fences and are skipped by the documentation validator until the construct lands.
- **Proposed** means the design has not been approved.

Both source editions are implemented. New projects use edition 2, which keeps edition-1 meanings and requires named mixer spellings. See [edition 1](edition-1.md), [edition 2](edition-2.md), the [semantic JSON mapping](semantic-model.md), [accepted syntax](accepted.md), and the [EBNF appendix](appendix.ebnf).

The Go tests check every runnable Cicada example in this directory, <code>docs/manual</code>, and the repository README with the same parser, semantic checks, and engine compilation used by <code>cicada check</code>. They also require each example to select edition 2. <code>TestDocumentationEBNFMatchesGrammarDSL</code> checks that the generated appendix matches the grammar DSL in <code>language/grammar/grammar.go</code>.

The appendix is generated by <code>go generate ./language/grammar</code>. The EBNF test compares the complete generated file, so a syntax change cannot leave its productions behind. The DSL also carries parser precedence, token priority, fields, and test cases; the appendix explains precedence and lexical priority but does not encode those parser-generation details.
